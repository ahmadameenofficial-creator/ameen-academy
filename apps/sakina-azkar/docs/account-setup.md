# ربط Google الاختياري وحفظ المتابعة

كل مزايا القراءة والعدّ والمتابعة والمحفظات تعمل بدون حساب أو قاعدة بيانات. يضيف الربط حفظ سجل المتابعة (آخر سنة) وعدّادات الصباح والمساء الحالية واستعادتها بين الأجهزة. المحفوظات والإعدادات محلية لكل حساب أو زائر، ولا تتزامن إلى الخادم في هذا الإصدار. لا تُنقل بيانات الزائر تلقائيًا إلى حساب؛ تسجيل الخروج يعيد بيانات الزائر الأصلية.

## إعداد مشروع Vercel الحالي لسكينة

استخدم المشروع الحالي الذي يخدم `azkar.ameen.academy`، وجذر البناء `apps/sakina-azkar`. لا تغيّر مشروع الأكاديمية أو نطاقه أو إعداداته. أضف في إعدادات بيئة مشروع سكينة، دون إرسال الأسرار في الشات أو إدراجها في Git:

- `SAKINA_DATABASE_URL`: اتصال PostgreSQL الحالي لسكينة، أو اتصال منفصل بصلاحية إنشاء schema وجداول. يمكن استخدام قاعدة إحصائيات سكينة الموجودة؛ البيانات الشخصية تستخدم `sakina_personal`، ولا تمس جداول الأكاديمية أو الإحصائيات.
- `SAKINA_GOOGLE_CLIENT_ID` و`SAKINA_GOOGLE_CLIENT_SECRET`: OAuth client من Google، من نوع Web application.
- `SAKINA_ACCOUNT_SECRET`: سر عشوائي مستقل لا يقل عن 32 حرفًا، ثابت بين عمليات النشر. يُستخدم محليًا لتوقيع الجلسات ومعرفات الحساب؛ لا تستخدم placeholder خاصًا بـHTTPS proxy لهذا المتغير. تغييره يُبطل الجلسات ويغيّر معرفات الحسابات، لذلك احتفظ به آمنًا.
- `SAKINA_APP_URL`: `https://azkar.ameen.academy` (القيمة الافتراضية أيضًا).

في Google Cloud، اضبط OAuth consent screen، وتابع سياسة Google بشأن Testing/Test users أو Production. أضف redirect URI المطابق تمامًا:

`https://azkar.ameen.academy/api/account/callback`

للاختبار المحلي فقط يمكن استخدام `SAKINA_APP_URL=http://localhost:3100` وإضافة callback المقابل في إعدادات OAuth. لا تضع الأسرار في متغيرات `NEXT_PUBLIC_*`.

أعد نشر **مشروع سكينة الحالي** بعد الإعداد. بدون الإعداد الكامل تظهر حالة الربط غير متاحة وتبقى المزايا المحلية تعمل. القراءة بدون اتصال تعمل أيضًا للحساب على نفس الجهاز؛ تُعاد محاولة المزامنة عند الاتصال أو تركيز النافذة، ويمكن الضغط على «مزامنة الآن».

## الخصوصية والمزامنة

تستخدم Google flow مفاتيح PKCE وstate موقّعًا، ثم يتحقق الخادم من هوية Google عبر userinfo. لا تُحفظ access/refresh tokens ولا تُرسل إلى المتصفح، يُحفظ البريد الموثّق في سجل حسابات مستقل لإدارة الحساب، ويُعرض ذلك للمستخدم عند الربط. العمر والبلد والنوع بيانات اختيارية يضيفها المستخدم بموافقة واضحة، ويمكنه حذفها من المتابعة. تظهر لمالك سكينة في الداشبورد، ولا تُخلط مع إحصائيات الزوار المجهولة. الجلسة HttpOnly، SameSite=Lax، Secure في HTTPS. لا تقرأ واجهة المتابعة حسابًا إلا من الجلسة الموقعة؛ الكتابة والخروج يتطلبان Origin الصحيح.

الحفظ المحلي منفصل بمفتاح لكل حساب. تتزامن نسب الصباح والمساء وعدّاداتها والسجل بين الأجهزة؛ سجل الإحصائيات لا يتلقى هذه البيانات. كل عدّاد محدد يساهم بـ `count / repeat` ثم يؤخذ متوسط مساهمات العدّادات؛ الحرة والتعليمات لا تدخل في الهدف. التراجع والتصفير يخفضان النسبة، واليوم الجديد يبدأ عدّادات جديدة مع بقاء سجل الأمس.

الكتابة تستخدم revision لمنع طلب قديم من استبدال حالة أحدث. عند التعارض تُدمج الأيام والأقسام، وللقسم نفسه في اليوم نفسه تُحفظ آخر نسخة معدّلة حسب وقت الجهاز، بما فيها التراجع والتصفير. هذا لا يجمع ضغطات متزامنة لنفس الورد على جهازين؛ يستحسن القراءة على جهاز واحد في كل مرة وضبط ساعة الجهاز. مسح السجل يترك علامات حذف ذات وقت تعديل حتى لا تعيد المزامنة سجلات قديمة. السجل يحتفظ بآخر سنة فقط.

## التحقق

```sh
npm test
npm run typecheck
npm run lint
npm run build
# قاعدة اختبار PostgreSQL منفصلة فقط:
SAKINA_DATABASE_URL=postgresql://... node_modules/.bin/tsx --test tests/integration/account.test.ts
# يمكن استخدام Chromium الموجود في البيئة بدل تنزيل المتصفح:
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e -- tests/e2e/partial-progress.spec.ts tests/e2e/history.spec.ts tests/e2e/reading.spec.ts --workers=2
```

اختبار OAuth الآلي يستخدم استجابات Google محاكية. إتمام تسجيل الدخول بحساب Google حقيقي يتطلب الإعدادات أعلاه ويجب التحقق منه بعد النشر. اختبارات PostgreSQL والمتصفح تتحقق من الحفظ والاستعادة وعزل الحسابات والتراجع وتغيير اليوم.
